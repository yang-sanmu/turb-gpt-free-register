# 一键查套餐 / 查活刷新 AT

账号页的新旧两套界面均提供「一键查套餐」「一键查活刷新 AT」和「任务进度 / 历史」。启动时选择执行范围、预览账号数量并确认并发线程数（1–32，默认 3）。

- 可选范围：当前归档分类的全部账号、当前筛选结果（跨所有分页）、已勾选账号、最近一次查活 / 套餐查询失败的账号。搜索、套餐、Codex、2FA、日期条件只在「当前筛选结果」生效，以打开弹窗时的条件为准。
- 历史任务提供「重试查活失败项」「重试套餐失败项」。按该任务保存的失败明细分别选择阶段，后来已成功、已换邮箱或已删除的账号排除；套餐失败只补查套餐，不重新登录。未保存明细的旧任务不提供历史重试。
- 启动前显示可执行数量，排除已废及查活 / 套餐任务忙碌的账号。启动时在同一事务中重新选择并固定 ID 清单；执行前再次跳过忙碌或已经补查成功的账号，空范围不能启动。
- 查套餐使用现有 AT，不触发登录；缺少 AT 或查询出错计为失败并保存原因。
- 查活对所有非已废账号重新登录，包括 AT 尚未过期的账号。登录成功后保存新 AT，再同会话查套餐，两阶段结果分别统计。
- 已废、执行前已删除的账号跳过。忙碌、入队失败或执行错误计入对应失败数；已废跳过及查询失败的原因可在详情中查看。
- 与一键巡检共用持久化任务及防重锁，同一数据库一次只执行一个批量任务。账号处理结束后更新进度，排队不算完成。

进度每 5 秒刷新。关闭弹窗不会停止后台任务，也不会在普通轮询时反复弹出。再次点击任务入口、返回账号页或刷新页面，可以恢复正在执行的任务；关闭期间完成的任务会在返回时展示结果。历史统计及失败原因保存在 SQLite 中，不依赖浏览器存储。

浏览器关闭不影响服务端执行；WebUI 服务重启会将未完成任务标记为中断，保留已完成统计，不自动重放登录或套餐请求。

## 接口兼容

复用 `POST /api/accounts/inspections`，`mode` 可选 `inspection`（默认、原巡检）、`plan`（查套餐）、`live`（查活刷新 AT）。其他参数为 `workers` 和 `archived`（`0` / `only` / `all`）。存在活跃任务时返回 409 及已有任务。

`scope` 默认 `all`，还可用 `filtered`、`selected`、`failed`、`history_failed`。`filtered` 需传 `filters`（`q`、`plan`、`codex_status`、`totp_status`、`date_from`、`date_to`）；`selected` 需传非空 `account_ids`；`history_failed` 需传 `source_inspection_id`。失败重试仅适用于 `live` 和 `plan`，不受巡检的 AT 有效期跳过规则影响。范围不匹配的额外参数或未知参数返回 400，避免错误请求扩大执行范围。

`POST /api/accounts/inspections/preview` 接收相同参数，返回 `total_count`，不创建任务。预览与启动复用选择规则；列表状态可能变化，最终 ID 以启动事务内快照为准。历史记录保存 `selection`，账号 ID 仍仅存入独立快照表。

查活按实际登录页面分流：密码页进入密码 / 邮箱 OTP；验证码页先请求发码；邮箱 OTP 后进入 MFA 时继续提交本地 TOTP，完成后才交换 AT。缺少 MFA 密钥、未知登录页、收码超时只表示本次验证未完成，不判废。iCloud 等待时长未在此改动中调整。

历史接口保持不变，新增 `mode`、`processed_count`（含跳过的已处理数）和 `failure_count`（保存的失败 / 已废跳过详情数）。旧记录缺少新字段时仍可展示。原有选中账号操作继续可用。
